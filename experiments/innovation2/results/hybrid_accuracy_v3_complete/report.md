现在的新方案是 **“两类信息联合召回，视频证据独立核验”**，核心是把“找候选”和“确认身份”分开。

流程如下：

**视频 → 两类描述 → 联合检索Top-5 → 受控标注 → 独立视频核验 → 最终结果**

1. **保留两类互补信息**
   - 旧式描述提供可能的地标、文化符号名称，作为**身份假设**。
   - 结构化描述记录主体、外观、背景和可读文字，作为**观察证据**。

   本轮实验复用了此前保存的两类描述。

2. **联合召回知识库候选**
   
   把身份假设与观察证据合起来做文本检索，取Top-5。这样既保留旧描述的命名能力，也利用结构化文字证据弥补遗漏。

   **身份假设只能帮助找候选，不能直接证明识别正确。**

3. **让模型观看视频并生成受控标注**
   
   模型结合视频和候选知识生成标注，最终文化符号必须属于候选集合，否则输出 `unknown_symbol`。不再仅因观察描述没有命中关键词就提前拒绝。

4. **对输出实体做独立核验**
   
   核验器查看 **4张视频关键帧、候选的知识库定义和观察证据**，判断具体身份是否成立。它不读取前面的命名假设、检索分数或GT，避免把检索结果当成证明。
   
   独特外观、布局、服饰或活动组合可以支持接受；只有同类、同景区等关联，或证据不足，则拒绝。实体范围按照知识库定义判断，不强求整个建筑群同时入镜。

5. **区分运行错误和未知实体**
   
   JSON格式错误先做受限恢复，不能新增观察内容；无法恢复就记录运行失败，不能冒充“正确拒识”。

另外，当前参考图均未审核，因此**这版没有使用参考图检索或核验**。它采用的是文本联合召回＋视频视觉核验。

同一批20条开发样本上，准确率从A基线的 **70%提升到90%**；剩余两条错误都发生在召回阶段。论文上可以围绕“身份假设与观察证据分离、独立核验降低误拒”组织方法，但各模块的贡献还需要消融实验验证。
